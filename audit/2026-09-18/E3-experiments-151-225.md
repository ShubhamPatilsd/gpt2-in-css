## 2. Mechanism families

### A. HVAR variable-font dot products + CSS Grid/block-flow argmax over the full 50,257-token head (151–165, 176–178, 221–224)
The core stack: each token is a glyph whose advance width is an HVAR-interpolated dot product of the hidden vector (font-variation axes) with a quantized weight row; `max-content` sizing takes the maximum; bit-packing recovers the token ID.
- Best measured: standalone coarse head settled mutation **527.7 ms** (global11 inline-tie, 156) / **683.9 ms** (row-int10 3x256, 162); composed exact loaded head **2,741 ms mean / 2,709 ms median / 3,810 ms p90** (178) with 30/30 exact checks; cold loads 43–65 s.
- Blocker (docs' words): "the decisive cost tracks shaped glyph/line count" — ~50.5k text-shaping calls per prediction are irreducible in this design; containment (154), multiline text (163), min-content words (168), and shard-width tuning (157/161/177) all confirm that "fewer glyph runs do not remove the per-axis dot-product work or the 50,257-element CSS argmax". HVAR browser path caps at 256 axes/font, so ≥3 glyphs/token is a floor. Precision ceiling: Chrome floors variation coordinates to F2DOT14 (159), so int16 needs dither phases.

### B. Exact-avoidance routing / ANN over the vocabulary (166, 167, 169, 170, 207, 208, 215) — all Python-only
- Best: IVF 99.6 % recall at 128 probes (1.92x reduction); supervised 192 reps/group 95.3 %; LSH best 76 % at 41k rows.
- Blocker: "no exact operating point before essentially the full scan"; high-dimensional L2/box bounds prune ≤49 of 50,257 rows; learned routers top out ~60 % top-1. Every doc ends "reject for exact CSS inference". Nothing in this family reached a browser.

### C. Certified mixed-precision hot-2 head and its transport/topology ablations (172–206, 219, 220)
Cauchy-bound certified best-first search (214) with exact global-int16 rows for groups 0/1 replacing int10 rows in place (200).
- Best chain of retained wins (each broad 30/30): in-place hot-2 0.720x (200) -> direct `max(anchor-size())` outer node 0.772x (185) -> pruned dead timelines cold 0.649x (186) -> fan-in-16 materialized tree 0.975x/p90 0.894x (188) -> block-flow group max 0.921x (176) -> 3x256 coarse 0.980x/p90 0.881x (178). Absolute: ~5.3 s -> ~2.7 s warm mean.
- Blockers: (i) any transport that changes the number of font-run snaps or the anchor/container handoff breaks bucket identity by one bucket (219, 220, G128 in 199, packed decoders 194/196, chunk-slot 183) — "per-run metric snapping remains part of the exact browser contract"; (ii) gating/containment/packing that reduces DOM or shaping does not reduce latency because "Blink's live anchor dependency cost" dominates (183, 184, 189, 193, 194); (iii) hot-2 only covers 25.7 % of state paths fully; the serial exact-stage tail (23 stages, 14.2 s worst) "still scales poorly" (180 successor). The intrinsic-width wrapper cannot consume a gated maximum ("descendant sizing cycle or resolves to zero across the containing-block boundary", 197).

### D. Container-query gating of exact rows (209–211, 216–218; integrated as 172, 173, 184, 197)
- Best: isolated block gate B=4/B=8 **6.4/6.1 ms vs 160 ms** full grid (25x) on one 256-row group; per-token gate exact with mean 7.6 rows.
- Blocker: token-level carriers already slower than full grid (0.97x, 218); integrating block gates into the full head needs either duplicated int10 centers (172: 1.045x) or gate arithmetic that costs more than the shaping it saves (184: 1.086x); the progressive q12 wave adds ~27 ms local dependency cost and "does not amortize" at the production 418-row budget (1.051x, 211).

### E. Quantization/calibration analyses (212–214) — Python-only
- Best: q15 two-code repair 1,024/1,024 decision match with 6-glyph transport (212, no browser run); SVG-like 8-bit simulator PPL +4.3 % vs FP32 once calibrated on train corpus (213); row-int11 certified frontier 90.3x row reduction (214).
- Blocker: 213 explicitly omits Chromium filter/reduction rounding ("not certified browser error"); the "next acceptance test" against the actual Chromium SVG graph is not in this slice.

### F. CSS Grid/subgrid as numeric carriers (221–225, TinyStories 64-d and GPT-2 FC)
- Best: 50,257-candidate argmax 178 ms synthetic; Grid/subgrid FC 141.6 ms vs 629.8 ms timelines (4.45x).
- Blocker: "the recovered number exists only inside its own subgrid cell. CSS cannot gather 3,072 sibling-local values into the single `font-variation-settings` list" (225); counter-reducer escape failed; real head cost is the 50,257 live dot products (4.4 s as CSS expressions), not the 178 ms reduction.

### G. Text-node argmax alternatives (163, 168)
- Best: correct winner via `min-content` on 10/10 vectors at 1–64 groups.
- Blocker: 15–26 % slower than element controls at every size; full 197-group page hangs >180 s; U+2060 joiner defeats tie glyph selection.

## Notes on evidence quality
- "Narrow" screens are 2 samples; multiple docs (193, 198) show narrow wins reversing under broad runs. Only 30-sample results should be treated as decisions.
- Cold-load numbers are almost always single, order-sensitive observations (docs say "directional").
- Python-only families (B, E, 210, 217) contain no browser latency evidence; 210's "0.375x" is a glyph-count proxy, not time.

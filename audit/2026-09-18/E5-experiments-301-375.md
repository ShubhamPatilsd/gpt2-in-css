## 2. Mechanism families

### A. SVG filter tensor backend (entries 320–375 minus screens; ~45 entries, the bulk of the slice)
- Core primitive: weights-as-image × repeated input (`feComposite arithmetic`) → all-ones `feConvolveMatrix` row reduction, 256-wide shards. Split-sign R/G, then midpoint-centered products.
- **Best measured**: live-residual one-block chain 75–83 ms warm (29.4x vs 2.24 s HVAR block); 12-block graph 251 ms warm (but wrong token); bucketed 12-block correct tokens 11/477 at ~1.1 s + 3.0 s final LN; full head 0.67 s warm standalone; connected transformer+head 10.1 s; RGB-packed GELU + 4 scale bands 469 ms/12-block pass (2.77x) with 61/84 held-out winners; complete live 2-token block 952 ms; direct mixed-context c_proj 1.86x; centered FC 1.5–1.65x; projected-quality run: 2.64x perplexity, 25% agreement at ctx 4 (svg-causal-chromium-quality).
- **Blocker (in the docs' own words)**: every two-input/convolution/component-transfer boundary "cross[es] the quantized boundary. Even two-input addition does so" (8-bit materialization). Chromium returns zero for kernels >256 wide; `order="768 1"` empty surface; 33rd range band or 2x groups corrupts the graph; relocated live surfaces (`feOffset`/`feMerge`/`feTile`) read as transparent; monolithic 3072×768 filter 28 s; natural-64 winners 34–52/64; "the winner is a better acceptance metric than average coordinate error". No fix from linearRGB, P3/Rec2020, alpha, 16-bit PNG, HDR AVIF, Firefox, dithering, dual planes, or LN fusion.

### B. Higher-precision-transport attempts inside SVG (320, 323, 333–336, 353–357)
- **Best**: HDR lineage keeps 22–32 levels through 12 all-HDR stages; radix-16 digit arithmetic exact 256/256; alpha Boolean adders exact to 32 bits.
- **Blocker**: "a real matrix multiply is no more accurate than the ordinary 8-bit representation"; "no SVG primitive exposes that discarded remainder"; exact digit arithmetic needs 512–6,144 partial groups per 768-dot; Boolean 32-bit add already 2.76 s and connected 2-D matvec paints nothing.

### C. Custom-renderer prerequisites (312, 313) — Python-only skia
- **Best**: RGBA16F 20.5x lower RMSE than RGBA8 on held-out real 16×16 slices (0.0017 RMSE); F32 matches oracle to 1e-5.
- **Blocker**: F16 near 0.5 collapses to 3 levels; any byte table/RGBA8 barrier collapses; "changing the surface format alone is not a demonstrated solution"; no Chromium build attempted.

### D. Variable-font / HVAR vector backends (304, 305, 307, 310, 311)
- **Best**: projected-kv-qk — 4.73x attention speedup, 1.47 s at ctx16, RMSE ≤0.003, "preferred attention architecture". row-axis: 0.048–0.45 ms per input update once loaded.
- **Blocker**: 256-axis ceiling (Chrome and Firefox); 128 MB decompressed-font cap; WOFF2 rejection of large variation stores; region storage grows with square of input axes; COLRv1 paints one node per output (4.33x slower than gvar); connected attention+MLP leaves 1.30 s of "dependency-graph connection overhead".

### E. CSS layout/geometry transport and routing (301–303, 308, 309, 314, 315, 317)
- **Best**: slotted shadow roots carry exact values across two 400-level trees (enabled multi-stage blocks); packed preactivation transport exact at 48 bits/carrier, 6-bit packing ~960 ms for the isolated MLP.
- **Blocker**: size containment hides anchors from sibling mergers ("merger width resolved to zero"); `position-try most-width` is not an argmax; sibling-index router cuts bytes 48% but cold load only 2.2%; "further radix packing within width/height alone has reached its useful limit"; fixed cost "dominated by thousands of source/projection glyph operations, which packing does not remove".

### F. Scheduling / lifecycle (316, 319, 306)
- **Best**: SMIL `:has()` gate cuts two-block cold evaluation 22–24% (5.83→4.46–4.54 s) and drives a fully declarative 5-stage head (78 s, correct token).
- **Blocker**: SMIL signals are one-shot ("a recurrent CSS inference loop still needs a repeatable state machine"); 50k-row vocabulary scan is 70 s of layout; selective readers +28.7% slower with identical 119 recalcs/71 layouts; layer hoisting ±1%; audit finds "no demonstrated faster combination waiting to be enabled".

### G. Offline model-structure / quantization screens (305, 318, 322, 306-screen)
- **Best**: centered-LN algebra passes 264/264 stress (worst RMSE 0.00166); 2D-clustered asymmetric ranges 489/512 held-out; 0.6x query range 98.2% agreement.
- **Blocker**: post-training factorization "erase[s] nearly all of the learned transformation" (95%+ relative RMSE); exact chunk reuse is 1.06–1.35x *more* work than dense; offline winner screens disagree with Chromium ("offline winner screening cannot be used as the acceptance test").

## 4. Surprising / positive results not followed up

1. **SVG live-residual block at 75–83 ms warm (29.4x over HVAR)** and **12-block warm recompute 251 ms** (`svg-filter-matvec/RESULTS.md`). Speed was never the SVG problem; accuracy was. No successor combines the fastest SVG graph with the accepted HVAR head. The measured "correct" bucketed variant slowed to ~1.1 s + 3.0 s, and the natural-64 suite is stuck at 34–52/64.
2. **SMIL `:has()` gate −22–24% cold** on the two-block HVAR model (`smil-stage-scheduler`). Adopted only for the one-shot demo path; no experiment tried to re-arm it (e.g. `repeatCount`, `restart`, or per-token separate documents) for the recurrent loop, which the doc itself names as the open item.
3. **Centered-LN algebra passes all 264 stress cases offline** (`repo-optimization-audit-2026-09-17`) with worst q9 RMSE 0.00166 vs 1.685 for the rejected uncentered form — explicitly "unmeasured in the browser"; no browser fixture built.
4. **RGB-packed GELU + 4 scale bands: 2.77x faster with −2 held-out winners** (`svg-filter-bias-correction`). Doc says "next useful test is applying the same vector-wide re-encoding idea to other group-dependent nonlinear tables" — no such follow-up directory found in this slice.
5. **Contiguous-QKV graph: 14.2x smaller HTML, 12.4x fewer filter nodes, only 19% slower** (`svg-contiguous-qkv-batched-native-convolve`). Doc proposes grouping 2–4 heads to find the size/latency knee; not done.
6. **Projected KV cache: 4.73x attention speedup, but 1.30 s of the 2.23 s connected block is "dependency-graph connection overhead"** (`projected-kv-qk`). Inheritance and containment were tried; no experiment isolates what that 1.3 s is.
7. **Hierarchical 4-tap LN reduction 13.4% faster isolated with identical output** (`svg-live-*-hier4`) — dropped because connected accuracy fell; a hybrid (hier4 only on LN, box on QKV) was not measured.
8. **Skia F16 real-weight probe: 20.5x error reduction on held-out slice** (`skia-f16-real-matvec`) — explicitly left at 16-wide, no Chromium build, no wider dimension; the doc flags positive/negative rails as unimplemented.
9. **Alpha Boolean adders had zero style recalcs** (`svg-alpha-circuit-probe`) — the "why does the 2-D matvec paint nothing" question was named as the next bounded step and not answered.
10. **Position-try router 2.05x faster in isolation** — semantics wrong for arbitrary argmax, but no attempt to restrict it to a topology where `most-width` *is* the intended ordering (e.g. sorted candidates).

Row-axis full-model figures (5.9–47 GB) are projections. svg-filter-full-block "13x/29x" figures are warm same-page recomputation of one block, not token rates; the connected-with-head figure is 10.1 s. The svg-causal-chromium-quality perplexity result covers only 2 cases / 8 tokens.

## 2. Mechanism families

### A. HVAR / avar2 font arithmetic (the retained dense backend)
Entries: 19–26, 42, 48, 61, 70, 73.
- **Best measured**: pure 3072→768 HVAR projection **64.2 ms** (#61); real 255→256→256 tile inside one avar2 font **4.63 ms** (#26); exact compute-once CSS GELU + projection **111.4 ms** (#48); full block-0 MLP 251 ms best-warm / 0.45–0.70 s stable (#19); one complete connected block ≈0.6 s, two blocks 1.8–2.3 s (#19/#20).
- **Blocker**: Chromium's 256-axis-per-font cap; GELU cannot be applied before summing shards (#25, #42), so ≥3,072 scalar values must cross a CSS boundary per MLP. The oracle (#61) shows ~1.5 s of the 1.71 s two-block time is FC/state **vector transport**, not matrix math. DOM parser depth ~512 forces shadow-root staging (#19). `contain: layout/style` and `content-visibility` staging make it worse.

### B. Geometry → number transport (view-timelines, container units, anchors, packets)
Entries: 4, 5–9, 12–16, 44–45, 52–57.
- **Best measured**: direct 2-D container packet = **48 exact bits per carrier** (#55); 4×6-bit anchor packing exact (#13/#14); paired view-timeline transport 621 ms for 3,072 values (#4); unevaluated `calc()` in `*`-syntax property retains 48-bit integers (#52) → expression16 KV codec.
- **Blocker**: `anchor-size()` is never accepted inside registered numbers, typed `@function`, or `font-variation-settings` (#5–9, #15–16, #56) — a size-container boundary is mandatory. Typed `<number>` serialises at ~float precision (>24-bit packets corrupt, #52). Remembered-size latch fails (#53); list→function argument extraction fails (#54). Every coordinate still costs one container/timeline.

### C. Anchor-geometry arithmetic (`anchor-size()` + `calc()` as the ALU)
Entries: 10, 11, 17, 18.
- **Best measured**: SWAR 3072→128 in **617 ms** bit-exact (#18); 768→768 650 ms; attention 12×64 8.6 s (#17). Balanced trees fix the 99-term Chromium limit (#10).
- **Blocker**: O(weights) source (22–68 MB) and evaluation; named-anchor dependency graph does not scale; loses to fonts by 5–35×.

### D. Additive animation / compositor / counter / colour accumulators
Entries: 2, 3, 34(a,c), 38, 39–41, 46.
- **Best measured**: additive `font-variation-settings` 768→768 **149–165 ms** RMSE 1e-6 (#2); colour-mix 768×768 exact 660.9 ms (#34); counters 768×768 1,233 ms (#38).
- **Blocker**: Chromium animation-effect count (3,072 contributions dominate; shadow chunking dies at 512; transforms fail at 768²); counter scope is lexical (child increments invisible to siblings); compositor `plus-lighter` is 8-bit and collapses past 256 terms (#46). All 10–20× slower than HVAR.

### E. Font-relative metric channels (`ex/cap/ch/ic/lh`, GSUB/cmap14 selection, TTC)
Entries: 36, 62–63, 68–75.
- **Best measured**: 5 independent numbers per font instance at **0.0255 ms/update** (#73); direct parent→child metric chaining 0.0062 ms (#70); 4-metric bank 2.88× slower than HVAR/container at 256 rows (#72).
- **Blocker**: CSS units resolve from base metrics — GSUB `salt`, standard features and cmap14 selection are all ignored by `ch/ic` (#62, #63, #71, #36); VVAR not exposed (#68, #73); one face per 4–5 rows → thousands of faces / GBs RSS (#70, #72); TTC fragments load face 0 (#75); 16-bit advance can't hold two real dot products (#74).

### F. Bilinear / feature-selected fonts for attention scores
Entries: 27–30, 37, 64–66.
- **Best measured**: feature-selected QK + mixed-V persistent query update at ctx 32: **719 ms vs 8,432 ms** (11.7×, #65); bilinear HVAR 12×64 664 ms (#27).
- **Blocker**: once Q and K exist as CSS numbers, native typed `calc()` is 4–14× faster and exact (#27: 49 ms); fusing K-projection into the font destroys accuracy (#37). #65 is documented as superseded by `projected-kv-qk` (outside this slice).

### G. Native CSS arithmetic (typed `@property` stages, `if()`, `@function`)
Entries: 47, 49, 58, 67, 34(b).
- **Best measured**: fully typed softmax/value reducer ctx 64 fresh **≈56 ms** (#67); exact CSS GELU 3,072 values ≈24 ms (#61). Flex `exp()` softmax accurate but 4× slower (#34/#67).
- **Blocker**: O(n²) weights as CSS = 94 MB / 2.5 s per block (#58); unregistered expressions explode quadratically (#67 untyped invalid at ctx 64; #19 LayerNorm ~1M-term). Rule adopted: typed boundaries at every high-fan-out scalar.

### H. Full-runtime integration & scheduling (browser-gpt2 family)
Entries: 31–33.
- **Best measured**: **78 s/token** (12 blocks, 8 tokens, correct), 662 s total (#31). Component wins: expression16 KV −26–33 %, width reuse −28 % append at pos 32, locality 6× less style time for a one-head change.
- **Blocker**: none of the component wins reproduce natively (12-layer owned attention +20 %, lean bundle +11 %, width reuse ±); style recalculation ≈37–52 % of renderer time; KV retention via 129k delayed transitions; RSS 3–5 GiB; stage attribution impossible (0/24 passes fully observed).

### I. Alternative execution engines (AAT, custom Chromium F16, SVG/Skia, GSUB circuits, learned codes, grouped-MLP retrain)
Entries: 1, 32 (unconventional), 35, 50, 51.
- **Best measured**: GSUB glyph circuit 16 steps 7.0 vs 10.2 ms (−31 %, 2-coordinate toy, #32); Skia F16 20.5× precision vs RGBA8 (standalone, P).
- **Blocker**: `morx` stripped by OTS (#1); Chromium build needs 100 GB disk, 4.9 GiB free (#35); grouped MLP retrain 48 % error (#50/#51); learned codes 36 % error; alpha circuits time out; fused attention font 4–5× slower.

### J. Tokenizer / input
Entries: 43, 59, 60. GSUB BPE tokenizer works (81–270 ms, exact embeddings) but bounded to 4 tokens / ASCII; `contenteditable <style>` remains the only input channel.

## 4. Surprising / positive results with no visible successor

1. **avar2-hvar-real-gpt2-tile (#26)** — a real 255→256→256 GPT-2 MLP tile evaluates in **4.63 ms** inside one font, ~100× faster per-FLOP than the connected block. Only blocked by the 256-axis cap + GELU non-separability. No experiment in this slice tries an *approximate* separable decomposition validated against held-out states other than the failed retrain (#50), nor low-rank/two-stage avar2 chains, nor asking whether Chromium's 256-axis limit is OTS-configurable.
2. **font-metric-chain-probe (#70)** — direct font→font handoff of 5 values at **0.0062 ms/update** with no geometry. Combined with #73 (5 channels/instance) this is the cheapest transport measured anywhere in the slice; it was dismissed because of face count (924 fonts). No follow-up tried mixing it with avar2 (e.g. 5-metric handoffs *between* ≤256-axis tiles where fan-out is small, such as attention heads at 64 dims).
3. **anchor-swar-matvec 3072→128 in 617 ms bit-exact (#18)** — 5.48× over scalar; the doc explicitly declines to build the 768-output page. Not revisited for narrow exact reductions (e.g. argmax/head selection) where exactness matters.
4. **browser-native-compute shear-transform → `anchor-size()` fusion (#34)** — exact 16-term dynamic dots read directly from an additive animation's transformed bounding box, bypassing number materialisation. Explicitly "third choice"; never integrated.
5. **css-numeric-packets / css-vector-latch (#52, #54)** — unevaluated `calc()` in a `*`-syntax property survives with 48-bit integer precision and can be held/resumed; only used for the expression16 KV codec (#31), which showed −26–33 % component time but was not promoted because RSS didn't fall. No attempt to use the same expression latch for the 768-value block-state handoff (#19: +49 ms/block, 384 containers) or the FC preactivation boundary that #61 says costs ~1.5 s.
6. **exact-gelu-vector-oracle (#61)** — 26.6× ceiling if boundaries were free; this is the clearest quantification in the slice that *transport*, not fonts, is the bottleneck, yet family B's latest entries (#52–#55, 09-15/16) are packet-capacity probes, not a new bulk transport primitive.
7. **feature-selected-qk-all-heads (#65)** — 11.7× persistent-update speedup at ctx 32 and a working CSS-only nested-cache interface; the doc points to `projected-kv-qk` as successor (outside this slice) — verify in E2+ that the nested-cache inheritance idea survived.
8. **flex `exp()` softmax (#34→#67)** — accurate and geometry-native; kept only as fallback because typed CSS is 4× faster on fresh inputs. Not tested in the *native* 12-block runtime where style-recalc dominates and a layout-only reducer might trade differently.
9. **Locality diagnostic (#33)** — 6× less style time for a one-head change is the largest style-work reduction measured, but the integration (#32) got slower; the doc itself says the single-head ratio was never measured under all-head simultaneous change with a matched baseline.

## Skepticism notes
- Numbers marked (E) are projections: #18's 3.7 s, #42's 2,304 fonts / 1.86 GB, #50's 53.83 ms browser gate, #72's 2,304 faces.
- Python-only: #50 (retrain), #66's offline RMSE, #74's `real-feasibility.json`, #32's learned codes and Skia F16.
- #35 ran nothing.
- Multi-page "alternating" benchmarks in #19/#20 inflate absolute times (docs say so); only relative deltas are trustworthy there. #19's "251 ms MLP" is a best warm run; stable floor 0.45–0.70 s.
- #67's earlier 47.5× flex-vs-typed claim was retracted to ≈4× after the fresh-input audit; #67's 4.40 ms was repeated-state cache hits.
- #31's 78 s/token is the *only* validated end-to-end figure; every component win in #32/#33 failed to reproduce natively.

## 2. Mechanism families

### 2.1 HVAR font advances as dense matvec inside a transformer block (gpt2-block-css, gpt2-flat-12block-chain, gpt2-hvar-chain)
- **Best measured:** one real block-0 QKV in 168–197 ms (container packets); registered-property HVAR MLP 812.6 ms; packed-timeline FC → HVAR projection 184.5 ms (but RMSE 0.0305); 2-token attention+projection 0.785 s; 12 real blocks staged in 9.39 s (context 1, correct token). Warm 16-token K/V-reuse query mutation 2.38 s attention / 3.68 s through MLP.
- **Blocker (doc's words):** "The remaining cost is therefore the browser's element/dependency/layout graph, not primarily the matrix multiplication" — system-font ablation still leaves 79–87 % of wall time; "reducing glyph count or consolidating text runs cannot deliver the required order-of-magnitude improvement. The missing primitive is a way to read many HVAR advances as reusable numeric state without one timeline/property pipeline per output." Connected 12-block inherited graph produces wrong results (RMSE 10.4). Chrome stops propagating nested containers after ~512 levels; multi-million-px widths lose low-order bits (packing limit ≈24 bits per axis).

### 2.2 Fused / composed fonts (fused-attention-font-probe; composed-QK documented inside gpt2-block-css)
- **Best measured:** correct fused QK→exp→ΣV over a calibrated domain, RMSE 0.0017.
- **Blocker:** 4–5× slower than numeric CSS (layout 6.6 ms vs 0.06 ms); region count quadratic (8,384 HVAR regions, 10 MB TTF); Chrome rejects the WOFF2; only valid inside a per-layer calibrated score interval (layer-11 sample max error 0.64). Composed QK: 4.13× slower, 197,120 regions. Verdict: "keep font variation work linear in the matrix coefficients."

### 2.3 Geometry → SVG raster transport (geometry-raster-vector; HVAR→SVG handoff in gpt2-block-css)
- **Best measured:** 3,072 widths → raster column in 51 ms mutation, RMSE 0.0017 (8-bit-class). 4,608 QKV outputs → 64×72 raster in 296 ms.
- **Blocker:** the raster cannot be consumed by a second filter stage ("Q/K dot products collapse to zero"; monolithic sampler 657 ms and less accurate; fused filter >3 min). No successor in this slice.

### 2.4 Shadow-DOM / slot depth probes (forwarded-depth-probe.html)
- No saved results; purely a mechanism probe (anchor-size → container query → `--forwarded` across a 400-deep slotted shadow tree). Undocumented.

### 2.5 HVAR + Grid output head with coarse/fine cascades and coordinate dithering (#113–125)
- **Best measured:** accurate seven-phase selective head 1.03 s warm (staged, 256-axis shards), coarse 50,257-token scan ≈0.63 s of it; coarse-only global-int11 0.528 s. Connected 2-block + head 2.43 s.
- **Blocker:** Chrome floors normalized OpenType coordinates to F2DOT14 (flips near ties; dither repairs at 7+ phases but 8 phases on all 256 finalists = 5.8 s); a permanently visible 50k-node head costs 12.75 s per upstream mutation → **lifecycle staging required**, and no CSS-only phase controller reproduces the external rAF barrier ("Four dependent container-query/animation barriers collapse into one style fixpoint"). Cold load 60–75 s and ~137 MB runtime.

### 2.6 Certified best-first int10/int16 output head (#83, 84, 80, 126–150)
- **Best measured:** gated 6-stage cascade 4.806 s warm / 49.1 s cold, 10/10 dense winners (int10 upper 2.35 s alone). Two-plane merge is an exact parallel primitive (10/10 + ties).
- **Blocker:** every extension costs latency — 16 stages 5.63 s / 86.9 s cold; 61 stages 5.9 s / 199–228 s cold ("Each stage masks every previously visited group … quadratic"; packed masks fix bytes, not time: "remaining cost is the duplicated 197-source/197-match router at every dormant stage"); parallel tails/batches 8.6–14.9 s ("Chrome still pays for every eagerly shaped group"); one-plane merge loses 1/64-px token field at multi-million-px widths; browser bucket drift −6..+8 needs a 24-bucket allowance (and 27 with GSUB); group-91 scorer drift persists for wide uncertainty sets. GSUB and hot-2 precompute variants 0.56–0.84× speed.

### 2.7 Blockwise / groupwise Cauchy certificates on block-flow topology (#82, 96–107, 105–106)
- **Best measured:** groupwise cascade 1,979 ms mean (0.693× retained shard256 head), 10/10 fixtures; production-range (±266.2) 23-stage proof; selective q12 top-32 hard-tail 0.775×; six-font q16 fixes state 519 with cold 0.864×.
- **Blocker:** tail depth — production mutations 8.5–14.2 s on 11–23-stage states; batch-17 parallel wave 1.67× slower; per-row 96-axis carrier 5.29× slower (rejected); six-font q16 warm 1.08–1.29× slower; 197-way `anchor-size` max reducer computed 0 px in the full-vocab q16 page. Docs: "serial exact-stage depth still scales poorly in the hard tail"; "Do not build the proposed multi-wave tail until a wave can share or reduce exact row shaping."

### 2.8 Global-precision transport (q15/q16, lattice scale, integer axes) (#91–95)
- **Best measured:** integer fvar axes + `round(nearest, h/R*16384)` → 16/16 winners, max bucket error 1 (from 15), warm 3.65 ms on 192 rows. q15 six-glyph = accuracy of q16 at half the glyphs, ~1.00× time.
- **Blocker:** per-glyph HVAR advance/layout rounding still leaves 712/3072 buckets off by one (strict gate false); 1/64 lattice has a −0.5 px zero-axis base offset; full-vocab integration failed on the reducer, not the transport (10/38 via CSS decoder, 38/38 by width scan); 74.8 MiB WOFF2, cold 72 s.

### 2.9 Hot-row transport shortcuts (#79, 86, 108, 137–139)
- **Best measured:** none passed semantics with a speedup; compensated one-plane 0.777× but 0/2 correct.
- **Blocker:** negative advances in one font-fallback run do not subtract from a later run; coarse+residual buckets mismatch 2397/2560; GSUB cannot compute argmax, only select rows (0/512 rows removed).

### 2.10 Approximate / geometric search for the output head — offline only (#85, 109–111)
- **Best measured (NumPy):** HNSW 99.22 % recall needs 24,196 row scores and 1,028 sequential hops; fixed batched frontier 95.7 % at 1,894 rows; ball tree prunes to 50,118 of 50,257 rows.
- **Blocker:** none reaches 99 % under 2,000 rows; sequential depth incompatible with CSS. All "NO-GO"; never built in browser.

### 2.11 MLP axis-ceiling alternatives — offline (#89)
- Rank-256 FC keeps 0/10 winners; avar2 3-per-axis packing needs 10⁹–10¹² deltas. Retained: 12×256 exact sharding.

### 2.12 Tokenizer/embedding fonts (#87–88)
- Artifacts only (`build_metric_tokenizer_font.py`); no results in the directory.

## 4. Surprising / positive results without an obvious successor

1. **Integer fvar axes (`-16384/0/16384` + `round(nearest, h/R*16384)`) — #94.** Cut q16 bucket error from 15 to 1 and got 16/16 winners on the 192-row probe at 0.89× the time. Its full-vocabulary follow-up (#95) failed on the *reducer* (197-way `anchor-size` max returned 0 px), and the six-font cascade (#103) was only accepted as a cold/accuracy profile. Nobody re-tried the integer-axis transport with the working block-flow/fan-in-16 reducer as the *default* head, and the strict "every bucket exact" gate is still open (712/3072 off-by-one, attributed to per-glyph advance rounding, uninvestigated).
2. **Geometry → SVG raster in one filter pass — #78.** 3,072 values in ~50 ms with 0.0017 RMSE and only 3,085 elements; that is far cheaper per value than any timeline/container transport in gpt2-block-css. The only follow-up (HVAR→SVG handoff) stalled because the raster could not be re-consumed by a second filter; no experiment tried the reverse direction (raster → few `anchor-size`/container readbacks) or SVG-only arithmetic on that raster.
3. **HVAR shaping itself is cheap — HVAR_SHAPING_EXPOSURE.** 9,216 real FC glyphs shape in 111–136 ms regardless of 3 vs 9,216 layout objects; exposure to CSS numbers costs 9.7×. This is the clearest quantification of where time goes, and no entry in this slice attacks "read many advances as numeric state" directly (the container-packet path caps at ~24 bits/axis and ~512 nesting levels).
4. **Warm K/V reuse — GEOMETRY_FULL_TAIL.** Query-only mutation at 16 tokens is 2.33 s vs 6.47 s cold navigation (2.8×), yet the "not yet a complete autoregressive step" caveat (fixture mutates a slot rather than appending) was not closed within this slice.
5. **Groupwise cascade 0.693× vs retained head with only 4 paired samples — #96.** The doc itself says "Four samples establish a strong direction, not a final broad benchmark"; a broad paired benchmark of the six-stage direct-target cascade against the retained shard256 head was not saved anywhere in this slice.
6. **Blockflow gate with bound glyph was *faster* than without (49.6 vs 85.7 ms) — #99.** Explicitly "not treated as a speedup claim" and never explained.
7. **Global-int11 coarse head 0.528 s warm (#114) and int10 upper head 2.35 s (#145)** are both much faster than every certified cascade built on them (4.8 s+); the gap is routing/exact-stage overhead, quantified only indirectly.
8. **Selective q12 top-32 (#104): 22.5 % hard-tail improvement** — but the doc notes both pages inherit the state-2032 error; no follow-up combined selective q12 with the six-font q16 accuracy fix.

## 5. Skepticism notes

- Many "speedups" in this slice are single-process or ≤6-sample paired runs (gpt2-groupwise-cauchy-blockflow-cascade: 4 samples; compensated-oneplane: 2; q16-sixfont: 6 alternating). Cold-load numbers vary 46–75 s for identical sources (#136 notes 49.1 vs 75.4 s).
- Offline-only entries (#80, 83, 84, 85, 89, 91, 107, 109, 110, 111) contain no browser measurement; their "groups"/"rows" are work models, and #84 explicitly shows the dependency-depth model failed to predict browser latency (B=4 modeled best, measured 1.7× slower).
- Correctness contracts are mostly "global-int16 target at Chromium-realized F2DOT14 coordinates", not float-exact; the target matches float on 1,016–1,024/1,024 states depending on doc.
- `gpt2-block-css` timings span Sep 8–15 with several rejected fixtures acknowledged as invalid (projection-easing tail, WOFF2 fallback font); only the numbers quoted in the nine md docs were used here.

# Global output-target precision screen

## Decision

**Probe global q15 in Chrome.** It offers a plausible joint accuracy and speed
improvement for the exact rows without changing GPT-2-small's architecture or
checkpoint.

Across the 1,024 production hidden states, mathematical global q16 preserves
all original-float GPT-2 winners. Global q15 preserves 1,023/1,024, far better
than lower global or rowwise precisions:

| Global precision | Float-winner matches | Weight RMSE |
| ---: | ---: | ---: |
| q11 | 997/1,024 | 5.035e-4 |
| q12 | 1,007/1,024 | 2.518e-4 |
| q13 | 1,016/1,024 | 1.259e-4 |
| q14 | 1,014/1,024 | 6.293e-5 |
| **q15** | **1,023/1,024** | **3.146e-5** |
| q16 | 1,024/1,024 | 1.573e-5 |

## Transport opportunity

Global q15 splits exactly as `code = high*128 + residual`. Three 256-axis
shards per plane require six glyphs per row, half the current global-q16
twelve-glyph transport. High and residual codes both stay within ±127. Across
the full vocabulary, maximum shaped advances are 6,858 units for the high
plane and 37,608 for the residual plane, so every face stays inside uint16
before CSS scaling.

The existing q16 browser backend has now changed one newly tested original/q16
winner despite mathematical q16 being exact on the corpus. A contender probe
must therefore compare **browser-realized** q15 and q16 against original float
top contenders, especially state 519 (float/q16 token 37848, current browser
q16 token 2032) and state 547 (the sole mathematical q15 mismatch).

# Independent review of input ownership and stage transfers

This is a source review, not a new performance measurement. The native receipt diagnostic did not establish complete stage proportions; its partial timings are not used to rank the candidates below.

## Vocabulary ownership

`browser_gpt2_head_locality.py` moves the common axis-list expression onto `.head-input-bank` and substitutes the resulting custom property at the coarse and fine scoring owners. That placement is consistent with the actual native runtime: `.head-input-bank` explicitly assigns all 768 normalized `--hN` values and retains them with delayed transitions. Making their registrations non-inheriting therefore does not remove the values from their actual owner. The audit read also targets this owner.

The baseline already declares `font-variation-settings` at two elements, `.full-head` and `.head-fine`; rows inherit the computed font property. Consequently, this change must not be described as replacing 50,257 separate font-setting evaluations with one evaluation. The unregistered axis-list bundle substitutes the input variables at the bank, while arithmetic can still evaluate when the two font-setting declarations compute. The clearest intended difference in `private-inputs` is reducing the 768 raw input properties inherited into the scoring descendants. Every score still depends on the new input, so the entire vocabulary generally needs rescoring for a new token.

The helper checks for both original setting declarations and all 768 input registrations. After this review, it also rejects any remaining raw `var(--hN)` reader after the two original setting declarations are removed. This protects against silently privatizing a value still needed by another descendant. The owner must remain the actual retained bank when applying the transform to a native runtime.

The component probe supplies saved real hidden vectors to the bank, verifies the winner and retained inputs, checks absence of raw values on a scoring row in private mode, and revisits the first vector. Its source reference contains 38 vectors, 28 distinct expected winners, and updates through epoch 39, exercising the separate head epoch transport beyond the old four-bit range. It is externally driven component evidence. It does not itself exercise the native bank's active-to-held transition against changing upstream residuals; that remains a native integration requirement.

Two initial measurement hazards were fixed by the root agent before its head runs: timed settling now reads a two-number geometry witness rather than serializing full computed-property maps, and the RSS sample list is frozen before its peak is calculated. Planned update count, initial check, and external write count are recorded. Geometry observation can still flush renderer work, and the stability reads and their 30 ms gaps are part of measured elapsed time. Compare matched inputs and process repeats, and report renderer counter deltas alongside elapsed time.

## Transfer candidates ranked by specificity of the source change

1. **Read only the needed residual bank.** `probe_native_reused_loop.py::loop_parts` ordinarily attaches 1,538 animations to the reader: two banks of 768 vector coordinates plus one generation stamp each. Its existing selective branch reads the prior bank's 768 coordinates, the prior stamp, and the current bank's acknowledgement stamp: 770 animations. This is a concrete reduction in animated reader fields, not a prediction of a 50% timing improvement. The old caller coupled selection to the broader `liveness` option and its property resets. The dense agent now owns an independent `loop-selective` ablation, preserving both stamp channels and native capture/advance rules.

2. **Narrow timeline visibility only at a proven common ancestor.** Loop bank sources and their reader share the core subtree; the context bridge's source and receiver share the QKV-stage subtree. Their `html`-level timeline declarations are candidates for narrower ownership, subject to exact DOM ancestry and native rearming tests. The final core-to-head bridge crosses the core boundary, so moving all timelines onto the core controller would break that sibling transport. The earlier `timelines` scaling variant narrowed attention score timelines, not these residual/context bridge scopes; its result is not a measurement of this separate candidate.

3. **Keep the existing fused readers when changing dense input ownership.** `build_hybrid_twelve_block.py::matvec` already combines readback with bias, GELU for FC, and residual additions for attention and MLP projections. Adding a separate intermediary stage for those operations would duplicate existing work. The dense agent's normalized-input privacy and projection-axis-list tests address representation lifetime while retaining these fused numerical consumers.

4. **Treat bridge removal as an architectural tradeoff.** The context bridge carries 768 coordinates and a fresh generation marker from attention/cache ownership into the following dense graph. Direct inheritance could remove transport machinery, but it would also put the dense descendants beneath cache state unless the ownership structure changes. The earlier explicit-field/reset regressions show why fewer carriers alone do not establish a speedup. The final head bank likewise needs a durable epoch-matched input while the next core pass begins; eliminating that retention is a correctness change, not a local optimization.

These priorities identify bounded hypotheses from actual code. They are not a ranking of measured stage CPU cost or a recommendation to implement all candidates together.

## Native integration evidence policy

The driver now archives compile, run, and verification sources under unique phase directories and records differences from compilation. Generated artifact hashes remain an independent integrity check. Prior summary and numerical records are retained before re-verification. Different phase source revisions are reported rather than treated as generated-artifact drift.

The original residual RMSE threshold of 0.01 would reject the already measured twelve-layer baseline: 0.027228 at two tokens and 0.018306 at four. Before the new native cases, the root agent declared residual RMSE below 0.05 and cache RMSE below 0.01, with exact token and final-head agreement required separately. The audit implementation preserves those bounds and additionally requires finite 768-coordinate residual and normalized-head vectors, finite 1,536-coordinate KV vectors, and exact cache coverage for every retained position and layer with no duplicates. Absolute error values remain visible.

A failed independent verifier now leaves a failed summary and exception details. An incomplete run records no total elapsed time instead of inventing a zero; its last observed sample time remains available. Each consecutive token interval is marked continuing or terminal. The warm median contains continuing intervals only, so a completed two-token run has no warm median and one separately reported terminal interval.

Six standard-library checks exercise source revision archival, terminal separation, missing/duplicated/nonfinite/wrong-width readbacks, verifier failure preservation, incomplete timing, and the strict predeclared residual boundary. They load only the relevant driver functions with synthetic files, without a browser or model computation. Results and the tested source hash are in `integration-driver-validation.json`. No earlier browser artifacts were modified by these evidence fixes.

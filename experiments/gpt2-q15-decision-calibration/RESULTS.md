# Q15 decision-aware calibration

## Decision

**Promote production-calibrated q15 to the browser contender.** Two integer-code
adjustments remove nearest-q15's sole mathematical winner mismatch and its sole
remaining production-bucket mismatch across all 1,024 hidden states, while
preserving the same six-glyph radix-128 transport.

This does not change GPT-2-small's architecture or source checkpoint. It changes
two values in the quantized approximation used to transport the existing output
matrix through fonts.

## Result

Nearest global q15 matches the original float output winner on 1,023/1,024
states. Its only mathematical mismatch is state 547: float chooses token 15 and
nearest q15 chooses token 405.

The first one-code repair screen found four moves large enough to reverse that
decision. The selected move is:

| Field | Value |
| --- | ---: |
| Token row | 15 |
| Hidden dimension | 496 |
| Q15 code | -1887 -> -1886 |
| State-547 logit improvement | 0.0247228 |
| Corrected state-547 margin | 0.0147235 |
| Original float-winner matches | **1,024/1,024** |

At the production 1/256 score lattice, this first repair still leaves state 493
tied into token 17 instead of q16/original token 82. A second one-code screen
against the actual global-q16 bucket contract selects:

| Field | Value |
| --- | ---: |
| Token row | 82 |
| Hidden dimension | 36 |
| Q15 code | -2913 -> -2912 |
| Global-q16 production bucket matches | **1,024/1,024** |
| Original float winners after bucketing | **1,024/1,024** |

Under radix 128, both moves change only residual digits: token 15 changes -95
to -94 while its high digit remains -14; token 82 changes -97 to -96 while its
high digit remains -22. Glyph count, face count, axis topology, and all CSS
scheduling therefore remain unchanged.

The rounded *float* scores themselves choose token 17 on state 493 because its
0.00150 margin is below the current bucket resolution. Global q16's quantized
score bias instead preserves original token 82 there. The second q15 move
deliberately matches that production q16 contract, so it reproduces the
original/q16 winner rather than the rounded-float tie.

The global weight RMSE changes from `3.1462745370604e-05` to
`3.146274820173476e-05`. The increase is negligible because this is two codes
out of 38.6 million, but the selection criterion was decision preservation
rather than RMSE improvement.

## Scope and limitation

This is exact for the 1,024 browser-realized production hidden states, not a
proof over the complete 768-dimensional activation domain. The calibration must
still pass the low-margin Chrome contender suite, especially states 493, 519,
and 547. A browser failure would implicate font/layout transport rather than the
q15 decision model.
